# The checks

Each check holds one claim the README makes to the thing it is a claim
about. `make check-c` runs the ones that need only a compiler and a model;
`make check-python` the ones that compare with sentencepiece, Silero's
Python, torchaudio or the corpora, each skipped with a line when what it
needs is not there.

tests/data/test.wav is Silero's own test recording (MIT, from the silero-vad
repository), a minute of English lecture; test.probs.txt is the VAD's
probabilities for it as vadito writes them; test.v2.json and test.v3.json are
`ref`'s transcripts of it, and test.v2.fast.json and test.v3.fast.json its
transcripts in the fast mode (`--fast`). tiny.pkf is `pktito-tools tiny`'s
output, a 1.2 MB model with random weights and every tensor, param and piece
type, and tiny-diar.pkf `pktito-tools tiny --diarizer`'s, a diarizer's of
117 KB.

When a change to arithmetic is meant - a rounding, an order, a kernel's
definition - test.v2.json and test.v3.json are regenerated from `ref`
(`PKTITO_KERNELS=ref ./pktito-c --json -m MODEL tests/data/test.wav`, and
with `--fast` the .fast.json), and the change carries its `wercheck.py`
numbers against the run before (CLAUDE.md, "Measuring").
